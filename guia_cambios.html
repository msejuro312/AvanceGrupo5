Resumen de todo lo que se arregló y agregó en AvanceGrupo5: login con roles, PDF de órdenes de compra, dashboard, edición/eliminación de OC y la nueva apariencia basada en el proyecto PROYECTO_LP2_GRUPO_B.

Commit local: 10f6e44 · Rama: master · Backend: Spring Boot 4 (Java 24) · Frontend: Angular 21 + Bootstrap 5

1. El problema que teníamos

No se podía ingresar al sistema con usuario y clave. La causa era doble:

  • La base de datos solo tenía sembrado un usuario (admin / 123) que nadie conocía, mientras que Spring Security tenía otros usuarios internos (admin/admin123, user/user123) que no servían en el formulario web.
  • El frontend enviaba siempre las mismas credenciales fijas (user:user123) en todas las peticiones, sin importar quién había iniciado sesión.
Solución: ahora la base de datos siembra los dos usuarios oficiales con sus roles, el login valida contra la BD, y cada petición viaja con las credenciales del usuario real que inició sesión.

2. Lo que cambiamos en el Backend Spring Boot

a) DataSeeder — src/main/java/com/serfagab/config/DataSeeder.java

Es la clase que llena la base de datos cuando arranca el proyecto (solo si está vacía). Ahora crea dos tipos de usuario y dos cuentas:

Tipo admin   = new Tipo();   // id 1, descripción "administrador"
Tipo usuario = new Tipo();   // id 2, descripción "usuario"

Usuario adminUser = ...      // login "admin", clave "admin123", tipo administrador
Usuario userConsulta = ...   // login "user", clave "user123", tipo usuario

Como application.properties usa ddl-auto=create, cada vez que se levanta el backend la BD se recrea y estos usuarios vuelven a existir. Por eso el login siempre funciona.

b) SecurityConfig — src/main/java/com/serfagab/config/SecurityConfig.java

Define quién puede entrar a cada endpoint. Regla nueva: leer es libre, escribir es solo del admin.

Método HTTPRutasQuién puede

Los usuarios internos de Spring Security ya coinciden con los de la BD (admin/admin123 = ADMIN, user/user123 = USER), así que la validación por HTTP Basic funciona con cualquiera de las dos cuentas.

3. Cómo hicimos el PDF de la Orden de Compra OpenPDF

Paso 1 — Agregamos la librería al pom.xml

<dependency>
    <groupId>com.github.librepdf</groupId>
    <artifactId>openpdf</artifactId>
    <version>1.3.43</version>
</dependency>

OpenPDF es gratuita (LGPL) y su API es casi idéntica a iText 5: trabaja con objetos como Document, Paragraph, PdfPTable y PdfWriter.

Paso 2 — Creamos la clase utilitaria src/main/java/com/serfagab/util/OrdenCompraPdf.java

Es una clase con un único método estático generar(orden) que recibe la entidad OrdenCompra y devuelve el PDF como un arreglo de bytes (byte[]):

  1. Crea un Document tamaño A4 y un PdfWriter que escribe sobre un ByteArrayOutputStream (el PDF se arma en memoria, no en disco).
  2. Agrega el encabezado: nombre del sistema, número de orden y fecha.
  3. Arma una tabla de información general (tabla de 2 columnas): fecha, estado, razón social del proveedor, RUC, celular, email, usuario que registró y observaciones.
  4. Arma la tabla de detalles (5 columnas): material, unidad, cantidad, precio unitario y subtotal, recorriendo orden.getDetalles().
  5. Agrega el TOTAL en S/ y un pie con la fecha de generación.
  6. Cierra el documento y retorna salida.toByteArray().

Paso 3 — El endpoint lo entrega como descarga

@GetMapping("/{idOrden}/pdf")
public ResponseEntity<byte[]> descargarPdf(@PathVariable Integer idOrden) {
    return ordenCompraRepository.findById(idOrden)
        .map(orden -> {
            byte[] pdf = OrdenCompraPdf.generar(orden);
            return ResponseEntity.ok()
                .contentType(MediaType.APPLICATION_PDF)          // dice "esto es un PDF"
                .header(HttpHeaders.CONTENT_DISPOSITION,          // dice "descárgalo así"
                        "attachment; filename=orden-compra-" + idOrden + ".pdf")
                .body(pdf);
        })
        .orElse(ResponseEntity.notFound().build());
}

Paso 4 — El botón en Angular

En orden.service.ts se pide el PDF como blob (archivo binario) y en ordenes.component.ts se crea un enlace temporal para descargarlo con el nombre orden-compra-N.pdf. El botón tiene el ícono de PDF de Font Awesome y lo ven tanto admin como user (es solo lectura).

4. Lo que cambiamos en el Frontend Angular

Guarda el usuario logeado en sessionStorage (dura mientras la pestaña esté abierta): guardarUsuario(), obtenerUsuario(), esAdministrador() (revisa si tipo.descripcion == 'administrador') y cerrarSesion().

b) Guard de rutas — src/app/services/sesion.guard.ts NUEVO

Si alguien intenta entrar a /materiales, /ordenes, etc. sin haber iniciado sesión, lo regresa automáticamente a /login. Está puesto en todas las rutas protegidas de app.routes.ts.

c) Interceptor — src/app/services/auth.interceptor.ts CORREGIDO

Antes mandaba fijo user:user123. Ahora toma el usuario de la sesión y arma el header Authorization: Basic usuario:clave con sus credenciales. Así el backend sabe de verdad quién es y puede aplicar los roles.

d) Login — src/app/components/login/* CORREGIDO

  • Al ingresar bien: guarda el usuario en la sesión y navega al dashboard.
  • Mensajes de error claros: distingue credenciales inválidas (401) de servidor apagado (error de red).
  • Botón INGRESAR con spinner mientras consulta.

e) Roles en pantalla

Cada componente CRUD pregunta esAdmin al construirse. Si no eres admin: se ocultan los botones Nuevo / Editar / Eliminar, la columna Acciones, el formulario de nueva orden y el selector de estado (en su lugar se muestra una etiqueta de color). Los filtros de búsqueda siguen visibles para todos.

f) Órdenes de compra — src/app/components/ordenes/*

  • Editar: abre un modal con proveedor, fecha y observaciones (usa el PUT nuevo).
  • Eliminar: pide confirmación con SweetAlert2 antes de borrar.
  • PDF: botón por fila.
  • FIX El selector de estado no refrescaba: el atributo [value] se aplicaba antes de que existieran las opciones. Se corrigió marcando la opción correcta con [selected]="e === o.estado".

g) Mensajes de éxito NUEVO

Al crear/editar/eliminar materiales, tipos de material, proveedores u órdenes aparece un toast verde de SweetAlert2 en la esquina superior derecha (mismo estilo que usaba el proyecto LP2), por ejemplo: "Material creado correctamente".

Carpeta: src/app/components/dashboard/ — ruta /dashboard. Es lo primero que ves tras iniciar sesión (antes entrabas directo a Materiales).

  • 4 tarjetas de estadísticas: total de materiales, proveedores, tipos de material y órdenes. Cada una con su ícono de Font Awesome, animación de entrada fadeInUp escalonada (0.1s, 0.2s, 0.3s...) y efecto de elevación al pasar el mouse, igual que el dashboard del LP2.

8. Cómo ejecutar el proyecto paso a paso

1
MySQL con XAMPP: abre el Panel de XAMPP y dale Start a MySQL. Ojo: si tienen instalado además el servicio Windows "MySQL80", hay que detenerlo primero (services.msc → MySQL80 → Detener) porque ocupa el puerto 3306 y genera "Access denied for user 'root'".
2
Crear la base de datos (una sola vez) en phpMyAdmin: CREATE DATABASE serfagab_db; — las tablas y los usuarios las crea solos el backend al arrancar.
3
Backend: abrir el proyecto en IntelliJ y ejecutarlo. Esperar el mensaje de que Tomcat inició en el puerto 8080. Si sale "Port 8080 was already in use", hay otra instancia corriendo: detenerla primero (botón Stop rojo).
4
Frontend: en una terminal dentro de la carpeta frontend-angular:
npm install (solo la primera vez) y luego npm start. Abrir http://localhost:4200.
5
Probar: ingresar con admin / admin123 (todo habilitado) y con user / user123 (solo consultas, filtros y PDF). En Órdenes: crear, editar, eliminar, cambiar estado y descargar PDF.
